# Specadoc

[English](README.md)

Specadoc — инженерный жизненный цикл для агентов, которые пишут код в Claude
Code, Codex и OpenCode. Он превращает запрос в письменный контракт, одобренный
план, реализацию с тестами вперёд, независимое ревью и компактную архивную
запись.

Specadoc запускается, только когда вы вызываете его по имени. Обычную работу с
кодом он никогда не перехватывает.

## Зачем

Агент, который работает только по сообщению в чате, забывает решения.
Он подгоняет требования под свой код и сам объявляет свою работу готовой.
Specadoc разделяет три вещи:

- Спецификация (`spec.md`) говорит, что должно делать изменение. После
  одобрения она стабильна.
- План (`plan.md`) хранит задачи, одобрения и доказательства. Он меняется по
  ходу работы.
- Ревью проводит отдельный `reviewer` только для чтения и никогда не агент,
  который написал код.

Детерминированные скрипты проверяют каждую фазу. Непройденная проверка
останавливает работу. Агент не может переписать план или ослабить тест, чтобы
её пройти.

## Режимы

| Режим | Что делает |
|---|---|
| `explore <request>` | Находит факты и проверяет идею. Файлов не пишет. |
| `propose <request\|slug>` | Пишет `spec.md` и `plan.md`, проверяет их и останавливается, чтобы вы одобрили план. |
| `apply <slug>` | Реализует одобренный план с тестами вперёд, выполняет финальную проверку и независимое ревью. |
| `light <request>` | Небольшое изменение в одной сессии. Обновляет спецификации возможностей, держит план в чате, папку изменения не создаёт. |
| `archive <slug>` | Сжимает завершённое изменение в один `record.md` ограниченного размера. Запускается только по запросу. |

Если режим не указан, Specadoc выбирает его по фиксированным правилам. См.
[Жизненный цикл](docs/ru/concepts/lifecycle.md).

## Роли

Ваша основная сессия агента — это **контроллер**. Он отвечает за требования,
архитектуру, одобрения и финальную проверку. Ограниченную работу он отправляет
трём ролям:

| Роль | Задача |
|---|---|
| `scout` | Одно ограниченное исследование только для чтения с отчётом фиксированной формы. |
| `worker` | Одна полностью описанная задача с минимумом решений, с тестами вперёд. |
| `reviewer` | Независимое ревью итогового диффа на соответствие спецификации, только для чтения. |

Каждая роль может работать на том же хосте или на другом рантайме. Файл
проекта `.specadoc.json` выбирает рантайм для каждой роли. Specadoc не
фиксирует модель: модель и уровень усилий берутся из установленного файла
роли. См. [Роли](docs/ru/concepts/roles.md) и
[Маршрутизация](docs/ru/guides/routing.md).

## Быстрый старт (Claude Code)

1. Добавьте маркетплейс и установите плагин:

   ```bash
   claude plugin marketplace add andreipan/specadoc
   claude plugin install specadoc@specadoc
   ```

   Чтобы остаться на релизе, добавьте его тег: `andreipan/specadoc@v0.1.4`.

2. Начните новую сессию в своём проекте.
3. Запросите предложение:

   ```text
   /specadoc:specadoc propose add rate limiting to the login endpoint
   ```

4. Прочитайте `docs/specadoc/<slug>/spec.md` и `plan.md`. Одобрите план или
   запросите изменения.
5. Запустите `/specadoc:specadoc apply <slug>`.

Для Codex (`codex plugin marketplace add andreipan/specadoc`), OpenCode и
обычных папок скиллов см. [Установка](docs/ru/guides/install.md). Полный разбор на примере см. в
[Ваше первое изменение](docs/ru/guides/first-change.md).

## Требования

- Python 3.10 или новее. Для файлов ролей Codex в формате TOML нужен Python
  3.11 или новее.
- Git в проекте.
- MCP-сервер, аутентификация и хуки жизненного цикла не нужны.

## Встроенные скиллы

Плагин поставляет ещё пять скиллов. Каждый работает без Specadoc.

| Скилл | Назначение |
|---|---|
| `tidy` | Чистка без изменения поведения перед финальной проверкой и ревью. |
| `codebase-design` | Решение контроллера об открытом интерфейсе или шве. |
| `domain-modeling` | Неоднозначные термины, состояния и инварианты на этапе уточнения. |
| `foreman` | Один постоянный исполнитель для длинной задачи. |
| `orchestrator` | Несколько контроллеров Specadoc, которые работают на один результат. |

См. [Сопутствующие скиллы](docs/ru/guides/companion-skills.md) и
[Orchestrator и Foreman](docs/ru/guides/orchestrator-and-foreman.md).
