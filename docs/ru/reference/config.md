# Конфигурация

[English](../../en/reference/config.md)

Эта страница описывает файл проекта `.specadoc.json`, определение корня
артефактов и конфигурацию, которую читают внешние запуски ролей. Пошаговая
маршрутизация ролей по рантаймам описана на странице
[Маршрутизация](../guides/routing.md).

В командах ниже `<skill-root>` — установленная папка `skills/specadoc`.

## .specadoc.json

`.specadoc.json` — JSON-файл в корне репозитория. Файл принадлежит проекту.
Закоммитьте его: его конфигурация действует для всех, кто запускает Specadoc в
репозитории. Файл необязателен. Без него действуют все значения по умолчанию,
описанные ниже.

JSON-схема:
[`assets/project-config.schema.json`](../../../skills/specadoc/assets/project-config.schema.json).
Скрипты читают файл из текущей папки, поэтому запускайте их из корня
репозитория.

Обновление плагина никогда не переписывает этот файл. Переустановка плагина
его не перезаписывает.

Полный пример:

```json
{
  "version": 1,
  "root": "docs/specadoc",
  "roles": {
    "controller": {"runtime": "claude"},
    "scout": {"runtime": "claude"},
    "worker": {"runtime": "codex"},
    "reviewer": {"runtime": "claude"}
  },
  "verification": {
    "environment": ["PATH", "APP_*"],
    "external_only": ["<integration suite config>"],
    "final": ["<suite command>", "<gates command>"],
    "probe": ["<command that reaches the test database>"]
  },
  "review": {"tidy": "required"}
}
```

Значения в угловых скобках — заполнители. Замените их командами вашего
проекта.

### Ключи

| Ключ | Тип | По умолчанию | Значение |
|---|---|---|---|
| `$schema` | строка | нет | Ссылка на схему для редакторов. Скрипты её игнорируют. |
| `version` | целое число, только `1` | нет | Версия конфигурации. Обязательна, если есть `roles`. |
| `root` | непустая строка | определяется, см. [Корень артефактов](#корень-артефактов) | Корень артефактов относительно корня репозитория. |
| `roles` | объект | нет | Рантайм каждой роли. |
| `roles.<role>.runtime` | `claude`, `codex` или `opencode` | см. [Как определяется привязка роли](#как-определяется-привязка-роли) | Рантайм, который запускает роль. `<role>` — это `controller`, `scout`, `worker` или `reviewer`. |
| `verification.environment` | список строк | все переменные, кроме фиксированного списка | Имена или маски переменных, от которых зависит проверка. |
| `verification.external_only` | список строк | нет | Фрагменты команд, которые запускает только внешний исполнитель. |
| `verification.final` | список строк | нет | Весь набор тестов и гейты, которые запускаются один раз перед первым ревью. |
| `verification.probe` | список строк | нет | Быстрые команды, которые запускает `doctor.py --probe`. |
| `review.tidy` | `required` или `optional` | `optional` | Обязателен ли проход tidy перед первым ревью `initial`. |

Каждый элемент списка должен быть непустой строкой. У каждого объекта роли
есть только ключ `runtime`. Модели, уровень усилий, права и инструменты в этот
файл не входят. Они относятся к установленным файлам ролей (см.
[Файлы ролей](#файлы-ролей)).

### Правила валидации

- Неизвестный ключ, роль, версия или рантайм — ошибка. Скрипты не переходят на
  значение по умолчанию.
- `roles` без `"version": 1` — ошибка.
- Файлу только с `root` ключ `version` не нужен.
- В схеме нет слоёв. Глобального или локального файла конфигурации нет.

Если скрипт не может прочитать файл, он останавливается с сообщением
`.specadoc.json: cannot read Specadoc config: <reason>`.

### roles

Каждая роль получает рантайм. Можно задать только часть ролей: роль без
записи использует следующий источник в порядке определения.

`roles.controller.runtime` не запускает контроллер. Ключ только проверяет
рантайм работающего контроллера. Если рантаймы различаются, маршрутизация
останавливается с сообщением
`controller runtime is <actual>, binding expects <expected>`.

Закоммиченный маршрут к рантайму, который отличается от рантайма контроллера,
считается согласием проекта. Тогда Specadoc отправляет промпт этой роли и
репозиторий в этот рантайм и не спрашивает заново для каждого изменения или
задачи. Запрос подтверждения от самого хоста Specadoc не контролирует.

Установите CLI каждого рантайма из маршрутов везде, где работает проект.
`doctor.py` показывает отсутствующий CLI как ошибку. Specadoc никогда не
переходит на другого провайдера. Если `worker` и `reviewer` используют один
рантайм, `doctor.py` выдаёт одно предупреждение.

### verification.environment

Принятые доказательства используются повторно, только пока дайджест
окружения не меняется. Дайджест хранит короткий хеш каждой переменной, а не её
значение.

Без этого ключа дайджест охватывает все переменные, кроме фиксированного
списка. Список содержит такие маски:
`PWD`, `OLDPWD`, `SHLVL`, `_`, `TMPDIR`, `*_TMPDIR`, `TMPPREFIX`,
`SSH_AUTH_SOCK`, `XPC_SERVICE_NAME`, `XPC_FLAGS`, `*PROXY*`, `*SESSION_ID`,
`*SESSIONID`, `*_THREAD_ID`, `*_PID`, `*_SOCKET`, `*_TOKEN`.

С этим ключом учитываются только перечисленные имена и маски. Остальные
переменные никогда не делают доказательства устаревшими. Если новая сессия
сообщает `environment changed: <names>`, перечислите только переменные, от
которых зависит проверка.

```json
{"version": 1, "verification": {"environment": ["PATH", "APP_*"]}}
```

### verification.external_only

Укажите фрагмент, по которому можно узнать каждую команду, которую может
запустить только внешний исполнитель. Например, имя файла конфигурации
интеграционного набора тестов.

`validate_change.py --phase plan` и `dispatch` отклоняют задачу, если её
`Verification` содержит такой фрагмент. Поместите локальную статическую
проверку в `Verification`. Реальный запуск назовите в
`External verification:`.

```json
{"version": 1, "verification": {"external_only": ["<integration suite config>"]}}
```

### verification.final

Команды, которые контроллер запускает один раз перед первым ревью: весь набор
тестов и гейты репозитория.

С этим ключом `specadoc_step.py finalize <slug> --run` запускает команды и
записывает коды выхода вместе со снимком области ревью. Затем
`validate_change.py --phase final` отклоняет отсутствующую, неуспешную или
устаревшую запись. Запись устаревает, если код изменился после запуска.

Без этого ключа контроллер сам запускает команды и записывает их командой
`finalize <slug> --observed '<run>'`.

```json
{"version": 1, "verification": {"final": ["<suite command>", "<gates command>"]}}
```

### verification.probe

Быстрые команды, которые доказывают, что оболочка имеет доступ ко всему, что
нужно для проверки. Например, один запрос к тестовой базе данных.
`doctor.py --probe` запускает каждую команду. Каждая команда должна
завершиться с кодом 0 за 60 секунд.

```json
{"version": 1, "verification": {"probe": ["<command that reaches the test database>"]}}
```

### review.tidy

Со значением `required` шаг `pre-review` отклоняет первый раунд `initial`,
пока `specadoc_step.py tidy <slug>` не запишет один проход по области ревью.
Повторному ревью новый проход никогда не нужен. Со значением `optional` проход
tidy — необязательный сопутствующий шаг REFACTOR.

```json
{"version": 1, "review": {"tidy": "required"}}
```

### Настройки хоста в Verification

Не помещайте настройки хоста или песочницы в `Verification` задачи. Команда,
которая начинается с `NAME=value` или `env`, фиксирует в плане рантайм одной
сессии. Другая сессия, песочница или валидатор потом запускают её иначе.

Настройте рантайм один раз для всех сессий, например в файле конфигурации
интерпретатора, который рантайм всегда загружает. Затем пишите команду без
префикса. `validate_change.py --phase plan` предупреждает о таком префиксе.

## Корень артефактов

Корень артефактов содержит все файлы Specadoc в репозитории. По умолчанию это
`docs/specadoc`.

Скрипты определяют корень в таком порядке. Побеждает первое совпадение.

1. Флаг `--root <path>` скрипта.
2. Переменная окружения `SPECADOC_ROOT`.
3. Ключ `root` в `.specadoc.json`.
4. Устаревший корень `docs/agent`, если он существует, а `docs/specadoc` нет.
5. Значение по умолчанию `docs/specadoc`.

`doctor.py` и `init_change.py` выводят определённый корень и его источник.

### --root

Большинство скриптов принимают `--root`. Значение задаётся относительно корня
репозитория. Для `specadoc_step.py` ставьте `--root` перед именем шага:

```bash
python3 <skill-root>/scripts/specadoc_step.py --root docs/changes status my-change
```

### SPECADOC_ROOT

Задайте эту переменную, чтобы сменить корень для одной оболочки без изменений
в репозитории. Пустое значение игнорируется.

```bash
SPECADOC_ROOT=docs/changes python3 <skill-root>/scripts/doctor.py
```

### Устаревший корень docs/agent

Старые проекты использовали `docs/agent`. Скрипт использует этот корень,
только если `docs/specadoc` не существует. Тогда каждый скрипт выводит
предупреждение в stderr.

Чтобы перенести устаревший корень:

1. Запустите `python3 <skill-root>/scripts/migrate_root.py` и прочитайте вывод
   пробного запуска (dry-run).
2. Запустите `python3 <skill-root>/scripts/migrate_root.py --apply`.

В рабочем дереве git скрипт переносит папку командой `git mv`. В перенесённых
файлах Markdown он заменяет каждое буквальное `docs/agent/` на
`docs/specadoc/`. Для других путей используйте `--from` и `--to`. См.
[Скрипты](scripts.md#migrate_rootpy).

## Как определяется привязка роли

Привязка роли — это рантайм, модель и уровень усилий, которые обслуживают
роль. Каждый запуск роли определяет привязку заново. Specadoc не хранит ни
снимок, ни одобрение привязки. Если вы измените файл роли или
`.specadoc.json`, следующий запуск использует новую привязку.

Рантайм каждой роли берётся из первого подходящего источника:

1. `roles.<role>.runtime` в `.specadoc.json`.
2. Установленная устаревшая роль-обёртка в файле роли контроллера (см.
   [Устаревшие роли-обёртки](#устаревшие-роли-обёртки)).
3. Рантайм контроллера, который вызывает роль.

Модель и уровень усилий всегда берутся из файла роли выбранного рантайма.
Отсутствующий или неверный целевой файл роли — ошибка.

Чтобы показать привязки изменения, запустите:

```text
python3 <skill-root>/scripts/role_routing.py --controller-runtime <runtime> --change <slug> --dry-run --compact --check-cli
```

Всегда явно указывайте рантайм вызывающего контроллера.

Если нет ни конфигурации маршрутизации, ни файла роли проекта, контроллер
использует зарегистрированную роль плагина (например, `specadoc:<role>` в
Claude Code). Если нет и её, контроллер использует субагента с переносимым
контрактом роли из `references/roles/<role>.md`.

## Настройки внешнего запуска

Роль, рантайм которой отличается от рантайма контроллера, работает через
`run_role.py`. В этом разделе перечислены файлы и переменные, которые читает
`run_role.py`. Флаги команды описаны на странице
[Скрипты](scripts.md#run_rolepy).

### Файлы ролей

| Рантайм | Файл роли | Ключ модели | Ключ уровня усилий |
|---|---|---|---|
| `claude` | `.claude/agents/<role>.md` (front matter) | `model` | `effort` |
| `codex` | `.codex/agents/<role>.toml` | `model` | `model_reasoning_effort` |
| `opencode` | `.opencode/agents/<role>.md` (front matter) | `model` | `variant` |

Уровень усилий должен иметь одно из этих значений:

| Рантайм | Допустимые значения уровня усилий |
|---|---|
| `claude` | `low`, `medium`, `high`, `max` |
| `codex`, `opencode` | `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`, `ultra` |

Пустое значение модели или значение, которое начинается с `<`, недопустимо.
Для файла роли Codex нужен Python 3.11 или новее, потому что резолвер читает
TOML.

### Устаревшие роли-обёртки

Устаревший файл роли может содержать такую строку:

```text
Default binding: runtime `<runtime>`, model `<model>`, effort `<effort>`
```

Резолвер читает эту строку, только если в `.specadoc.json` нет маршрута для
роли. Резолвер отклоняет обёртку, которая указывает на рантайм, отличный от
определённого. Когда вы переходите на маршрутизацию проекта, переносите
обёртки и `.specadoc.json` вместе.

### Права чтения в OpenCode

Для `scout` и `reviewer` в OpenCode `run_role.py` разрешает инструменты
чтения, поиска, веба и скиллов. Он также разрешает команды оболочки
`git diff`, `git log`, `git show` и `git status`.

Чтобы разрешить другие команды оболочки, добавьте записи в список
`permissions` во front matter файла `.opencode/agents/<role>.md`. Пишите одну
пару `key: value` на строку:

```yaml
permissions:
  - action: shell
    resource: <command> *
    effect: allow
```

`run_role.py` берёт только записи с `action: shell` и `effect: allow`. Ресурс
должен начинаться со слова команды. Ресурс, который начинается с `*`,
игнорируется. Перенаправление, `--output`, `--ext-diff` и `--pre` остаются
запрещены.

Если плагин хоста добавляет префикс к командам оболочки, перечислите формы с
префиксом. OpenCode проверяет команду после того, как плагины её перепишут.

### Переменные окружения

| Переменная | Кто читает | Значение |
|---|---|---|
| `SPECADOC_ROOT` | все скрипты артефактов | Корень артефактов. |
| `CODEX_HOME` | `run_role.py` | Домашняя папка Codex. По умолчанию `~/.codex`. `start` завершается с кодом 4, если не может писать в неё. |
| `XDG_DATA_HOME` | `run_role.py` | Основа пути к логу OpenCode, `opencode/log/opencode.log`. По умолчанию `~/.local/share`. `start` завершается с кодом 4, если не может записать лог. |
| `OPENCODE_CONFIG_CONTENT` | `run_role.py` | Существующая конфигурация OpenCode. `run_role.py` добавляет в неё своего агента `specadoc-external`. |
| `CLAUDE_CONFIG_DIR` | `collect_tokens.py`, `reviewer_reply.py` | Папка конфигурации Claude Code с транскриптами. По умолчанию `~/.claude`. |
| `CLAUDE_CODE_SESSION_ID` | `specadoc_step.py`, `collect_tokens.py` | Текущая сессия Claude Code. Шаги записывают её в `runs/sessions.json` для сбора токенов. |

`run_role.py` удаляет `CLAUDE_CODE_SESSION_ID` из окружения процесса роли.
Роль работает как отдельная сессия.

### Команды рантаймов

| Рантайм | Команда | Пишущая роль (`worker`) | Роли только на чтение |
|---|---|---|---|
| `codex` | `codex exec --json --ephemeral` с `--output-schema` | `-s workspace-write`, сеть loopback включена | `-s read-only` |
| `claude` | `claude -p` с `--json-schema`, `--strict-mcp-config`, `--no-session-persistence` | инструменты правки, `acceptEdits` | `Read, Grep, Glob, Bash`, `dontAsk` |
| `opencode` | `opencode run --standalone --format json --auto` с моделью `provider/model#effort` | правка и любая команда оболочки | права чтения из раздела выше |

Внешняя роль не получает серверы MCP и контекст контроллера. Назовите точные
файлы в брифе.
